# Coopanion 桌宠（DSH 插件）

把 [Coopanion](https://github.com/Pal-AI-Lab/Coopanion) 的桌面宠物搬进 DeepSeek Harness 的 Web 界面，
作为零侵入的 UI 插件运行。当前版本实现 **P0 桌宠本体 + P1 表现层 + P2 接入 DSH**——

**桌宠本体**

- **鲸鱼娘（DeepSeek Chan）** 站在界面下沿，可自由走动
- 待机动画：呼吸、眨眼、视线跟随鼠标、头发与裙摆的弹簧摆动
- **鼠标拖拽**：抓住她拖到任意位置，松手后落下，甩得快会晕
- **不挡界面**：只有光标落在她本体或她自己的界面元素上时才接管指针，其余区域完全放行

**说话与互动**

- **气泡说话**：文字逐字出现，标点处自然停顿，说完自动收起
- **表情与动作标记**：`【happy, jump】` 先播再说话，`<happy>` 打到那个字时播
- **提问气泡**：最多 3 个选项 + 自填框，按 `1`–`3` 可直接选，`Esc` 放弃
- **悬停按钮条**：靠近她时出现，可让她说话、换表情、做动作、走两步、装扮、睡觉
- **右键菜单**：装扮、状态气泡开关、音效、体型、漫游倾向、回到原位、隐藏
- **音效**：全部由 Web Audio 合成，不带任何音频素材，不增加额外体积

**状态气泡**

- 她头顶会显示**你正在做什么**：`正在看文件` / `正在写文件` / `正在查找` / `正在跑命令` / `等待回答` / 思考中的三个点
- **细到具体对象**：`正在看文件 · config.ts`、`正在跑命令 · pnpm test`——从工具参数里取文件名或命令，只留 basename 免得把完整路径摊在屏幕上
- 数据来自宿主侧的 `agent/status` 与 `tools/execute`，经 SSE 推给页面
- **对话永远优先**：她说话或提问时，状态气泡自动让位

**两个形象**

- **鲸鱼娘**（主形象，sprite rig：25 张纹理 + model.json）
- **Coo**（上游的第二个形象，**纯代码绘制**：SVG path，无纹理，三个文件共 49KB）
- 在设置面板「形象」一行切换，**按需加载**——默认用鲸鱼娘的人不为 Coo 付加载时间
- 两者共用同一套渲染内核（`assets/kit/`）；Coo 的三个文件与上游**逐字节相同**

**对话栈**

- 她头顶旁边显示**最近 3 条对话**（人话与她的回话），最新的贴着她的头
- 数据来自 DSH 的 `session/event`（`user/message` 与 `assistant/message` 的文本）
- **她说话/提问时整栈淡出让位**（透明度 1 → 0.04）
- 只显示 3 条、不做分页/附件/撤回——那些是 DSH 会话 UI 的活，重复造没意义
- 设置面板可关

**第三方形象包（可选）**

- **导入**：设置面板「形象」一行有「导入形象包」，选一个含 `figure.json` 的文件夹
- **安全**：包代码只在**沙箱 iframe** 里跑（`sandbox="allow-scripts"`，**不给 same-origin**），
  CSP 再限一道（`default-src 'none'`、`connect-src 'none'`）；宿主**只读文件、不执行**包代码
- **包不能吞点击**：她的包围盒与命中圆被收进舞台内；触摸事件只在页面刚给过指针输入后才算数
- 包放在 `~/.dsh/coopanion-pet-packs/<id>/`，插件升级不会丢
- **只支持「选文件夹」**：不引第三方 zip 库（省一个依赖），zip 请先解压再选

**独立窗口（桌面上那个她）** `[已验证]`

她可以**不依赖 DSH 窗口**待在桌面上——一个真透明、无边框、置顶、可穿透的窗口。

| 能力 | 说明 |
| --- | --- |
| **真透明** | `transparent: true` + `backgroundColor: '#00000000'`，只有她和她的气泡可见 |
| **鼠标穿透** | 默认穿透到桌面；光标移到她身上才接点击（`setIgnoreMouseEvents(true, {forward:true})` + 命中判定） |
| **置顶** | `setAlwaysOnTop(true, 'floating')`，浮在普通窗口之上 |
| **跨屏** | `setVisibleOnAllWorkspaces`，全屏时也在 |
| **全局快捷键** | 默认 `Alt+Space` 唤出/收起——**DSH 没聚焦时也管用** |
| **右键菜单** | 打开 DSH 主窗口 / 打开对话面板 / 让她说话 / 隐藏 / 穿透模式 / 置顶 / 退出 |
| **托盘** | 点图标唤出/收起，右键同一套菜单 |
| **独立聊天面板** | 列会话、读历史、发消息——**与 DSH 主面板操作的是同一批会话** |
| **13 个 `pet_*` 工具** | 含新增的 `pet_desktop`（读状态/启停独立窗口） |

**架构**（与上游 Coopanion、takboo/dsh-coopanion 同源）：

```
DSH 宿主进程
  └─ 插件 index.js
       ├─ 起一个本地 bridge 服务（刻意不在 /api 下 → 不走鉴权）
       └─ spawn Electron 子进程（desktop/main.cjs）
            ├─ 自己的静态服务（镜像 DSH 路由形状 → client.js 一个字不用改）
            ├─ 宠物窗口（透明/穿透/置顶）
            └─ 聊天面板窗口
```

**关键：独立窗口连的是同一条 `channel`**，因此 `pet_*` 工具、状态气泡、语音、审批
**全部照旧可用**——不是另一套。

**DSH 没开时**：她仍会出现（静态资源由 Electron 自己的服务提供），只是没有「Agent 指挥」的能力。

**怎么用起来 / 怎么排查**：见 [`docs/standalone-usage.md`](docs/standalone-usage.md)（操作指南 + 常见现象对照表）。

**Electron 运行时**：作为 `optionalDependencies` 声明，npm 安装时自动带（约 151 MB）。
也可以自己在设置里指定路径；**找不到时独立窗口不可用，但本体照常**——不假装成功。

**独立预览页**

访问 `/api/dsh-coopanion-pet/preview` 打开一个**带地板与墙的干净页面**，
只为「单独看她」——调形象、录屏、给别人演示。它加载的是**同一套客户端模块**，
因此能力与 DSH 页面里的她相同（说话、走位、收工具命令）。左上角有昼夜切换按钮。

**装扮**

- **8 套配色**：DeepSeek / Harness / ChatGPT / Claude / Gemini / Qwen / Kimi / MiniMax
- **2 套服装**：女仆装、冬装
- 面板可拖动，位置会记住

**走路足迹与帧率**

- 她走动时身后留一串**渐隐的脚印**（右键菜单或设置面板可关）
- **帧率三档**：省电（静止 12fps / 活动 30fps）、平衡（静止 24fps）、流畅（跟随屏幕）
- 静止时自动降帧——呼吸、眨眼这类慢动画看不出来，但省下大半 CPU

**全局说话热键**

- 在任何页面里按 **Ctrl+Shift+.** 她就说一句（按平台自动显示 Ctrl 或 Cmd）
- 走 DSH 的 `shortcuts` 服务，因此**输入框里打字时不会误触发**，也不抢终端与弹窗的键位
- 这个组合键会登记进 DSH 的快捷键速查，可在设置里改
- 拿不到 `shortcuts` 服务时（某些组合里没有）静默跳过，桌宠本体不受影响

**CUA 审批（可选）**

装了 [dsh-computer-use-win](https://github.com/Yu-tao-Li/dsh-computer-use-win) 时，
它的工具（`mcp__wincu__*`）要动用户的电脑之前，**由桌宠当面问一句**，而不是交给一个看不见的对话框。

| 档位 | 看屏幕（截图/查询/读窗口） | 操作（点、敲、拖） |
| --- | --- | --- |
| 每轮都问 | 问 | 一轮只问一次，答完本轮不再问 |
| 动手前问（默认） | 不问 | 一轮只问一次 |
| 问一次 | 不问 | 问一次，答「可以」后 30 分钟内不再问 |
| 不问 | 不问 | 不问 |

- 她不在时**不抢审批**：放行给 DSH 自己的通道，免得把用户的 CUA 卡死
- 超时、拒绝、政策层出错**一律按「不许」**处理（fail closed），不重试
- 只拦 `mcp__wincu__*`，其余工具一律原样放行——本插件不做通用审批
- 档位在设置面板「电脑操作审批」一行改，`pet_cua` 也能读改

**多语言**

- 界面文案有 **11 门**（与上游一致）：中文、英文、繁中、日、韩、德、法、意、拉美西、巴西葡、俄
- 默认**自动跟随浏览器语言**（zh\* → 中文，其余先落英文），也能在设置面板里手动指定
- 改完语言**立刻重挂桌宠**，不必刷新页面——界面文案在模块加载时定下，
  因此语言（与「显示桌宠」开关）一变就重建整层
- 配色名（DeepSeek、Claude…）是品牌名，不翻译

**Agent 能指挥她（P2）**

装了本插件后，Agent 多了 6 个工具，可以在对话中直接让她做事：

| 工具 | 做什么 |
| --- | --- |
| `pet_say` | 让她在气泡里说话，支持 `【表情, 动作】` 与 `<表情>` 标记 |
| `pet_ask` | 让她问用户一个问题（最多 3 个选项 + 自填框），用户的回答会作为新消息回到会话 |
| `pet_walk` | 走到屏幕某个横向位置，可让她跑 |
| `pet_act` | 做一个表情或动作（19 种表情、14 个动作） |
| `pet_dress` | 换配色或服装 |
| `pet_status` | 查她现在在不在、在哪、在做什么 |
| `pet_quiet` | 让她安静 N 分钟：关音效、不走动、状态气泡让位，到时自动恢复。不动用户的偏好 |
| `pet_set` | 改她自己的体型、漫游倾向、音效、状态气泡、走路足迹、帧率 |
| `pet_listen` | 录一小段话，交给 DSH 的语音输入插件识别，返回文字（可选，见下） |
| `pet_speak` | 用真实语音朗读一小段话（可选，见下） |
| `pet_voice` | 列出可用的麦克风，或换一个（可选） |
| `pet_cua` | 读或改电脑操作的审批档位（可选，见下） |

她不在（没有页面打开）时，工具会如实回报 `offline` 而不是假装成功。

**语音（可选，不声明为必需依赖）**

`pet_listen` 与 `pet_speak` 是**条件可用**的：宿主装了对应插件就能用，没装就如实回报、不假装成功，
也不会因此让桌宠本体加载失败——这两个能力**不写进插件的 `inject`**（`inject` 是必需依赖，缺一个整插件就加载不了）。

| 能力 | 接的是什么 | 未装时的表现 |
| --- | --- | --- |
| 听（识别） | DSH 自带的 `@deepseek-ai/dsh-experimental-voice-input-bundle`（SenseVoice 本地识别） | `pet_listen` 返回 `no-speech-plugin`，并说明装什么 |
| 说（合成） | [dsh-xiaomi-tts](https://github.com/ppy-web/dsh-plugin-xiaomi-mimo-tts) 注册的同源路由 | `pet_speak` 返回 `no-tts-plugin`，并说明装什么 |

识别**不自己搬 ASR**：DSH 的 `speechToText` 是宿主侧服务，浏览器端插件运行时拿不到
（客户端插件只有 `slots`/`connection`/`loader`/`modules`），因此由宿主半边调它，页面只负责录 WAV。
合成则绕宿主一圈：路由本来就能直接 POST，但走宿主能给出「没装那个插件」这句人话，而不是让页面拿到 404 去猜。

**不需要读它们的配置、也不需要 API key**：识别用宿主已选好的识别器，合成由 TTS 插件自己去调上游。

**按住说话**：**Shift+Space**（在 DSH 页面里按住就说，松开即识别）。
走页面内的 keydown/keyup——**DSH 的 shortcuts 服务只有 keydown、没有 keyup**，
因此拿不到「松开」的时机，只能自己监听。代价：只在页面有焦点时生效。

**录音时看得见**：她头顶会显示「正在听 3.2s」+ 音量条，松开后显示「识别中…」。
这是**替代原计划「假流式」的方案**——实测分片识别比整段更慢更不准（见
`docs/risk-verification.md`），而「录的时候看得见」才是真正缺的那块体验。

**识别结果的出口处理**（照搬上游 `src/asr/result.ts` 的判据）：
- **幻觉过滤**：模型在没人说话的音频上会吐出训练语料里的字幕（「谢谢观看」「字幕由…」），
  靠内容分不出真假，只能按名单拦；Whisper 类模型还会把声音标在括号里（`[Musik]`、`(звук пива)`）。
- **繁简归一**：逐字判断，只换表里有的字。**不引 OpenCC**（内联常用字表，覆盖范围小于上游，如实说明）。

**识别结果去哪**：两条路，运行时自动选。
- **填进输入框**（理想）：走 DSH 的 `conversation.input.activity` 槽拿 `inputActions`；
- **送进会话**（降级）：那个槽是 **single 类型且被官方语音输入插件独占**，装了它就填不进去，
  这时把识别文本作为**一条用户消息**发出（等价于「你说了这句话」，区别是会直接触发一轮对话）。

**先探测、再申请麦克风**：`pet_listen` 会先 `GET` 一次 `/speech` 问「你能不能听」，
确认可用才去 `getUserMedia`。否则没装语音插件时用户会先看到一个麦克风权限框，
白点一次拒绝——而他拒绝完拿到的还是「没装插件」。已验证：未装时调用前后
`navigator.permissions` 的 microphone 状态都停在 `prompt`，即从未申请过。

**她记得自己站哪儿**

刷新或重开页面后回到上次的位置（存的是占窗口宽度的比例，换窗口大小也不会跑出屏幕）。

**设置面板与提示词（P2）**

- 设置页多出一栏「桌宠」，**19 项**都能改，改完立刻生效（不必重载）：
  显示开关 / 状态气泡 / 走路足迹 / 双击说话 / 体型（滑块 0.5–10 倍）/ 气泡框大小 /
  字号 / 轮廓光晕 / 主题（跟随·浅·深）/ 称呼 / 漫游 / 帧率 / 触摸唤醒 /
  悬停按钮（勾选最多 6 个）/ 音效总开关 / 六类声音分开关 / 鼾声时长 /
  她自己能改什么 / 电脑操作审批 / 语言（11 门）
- 系统提示词里多一段，告诉模型她存在、有哪些工具、**什么时候不该用**
  （不要为了让她说话而每轮都调用一次工具，她是背景陪伴不是旁白）

形象、动画与渲染内核 **原样取自 Coopanion**，未作修改。

## 安装

需要一个带 Web UI 的 profile（`dsh web`、DSH 桌面端，或任何含 `@deepseek-ai/dsh-web-app` 的组合）。

**从 npm 装**（推荐）：

```powershell
dsh plugin --profile <你的profile> add dsh-coopanion-pet
```

指定版本：`dsh plugin --profile <你的profile> add dsh-coopanion-pet@1.9.0`

**从 GitHub 装**（跟仓库 main 分支）：

```powershell
dsh plugin --profile <你的profile> add "github:wangquanqing/dsh-coopanion-pet"
```

**从本地目录装**：

```powershell
dsh plugin --profile <你的profile> add "file:D:\path\to\dsh-coopanion-pet"
```

装完**重启宿主**（浏览器刷新不够，客户端模块需要重新装配）。桌面端由 Electron 独占管理其 profile，
请在桌面端的插件管理界面安装，不要直接对 `desktop` profile 执行上面的命令。

卸载：`dsh plugin --profile <profile> remove dsh-coopanion-pet`。

## 它做了什么

单包双面，两个半边各司其职，都不修改任何内置包文件：

| 半边 | 文件 | 职责 |
| --- | --- | --- |
| 宿主 | `index.js` | 静态路由；采集运行状态经 SSE 下发；注册 `pet_*` 工具；收页面回传 |
| 宿主 | `lib/channel.js` | 双向通道：命令编号、下发、等回执、超时兜底、离线判定 |
| 宿主 | `lib/tools.js` | 六个 `pet_*` 工具的定义与执行 |
| 宿主 | `lib/define-tool.js` | 把属性级 `required: true` 转成标准 JSON Schema（见下） |
| 宿主 | `lib/optional.js` | 可选接缝：探测语音识别服务与 TTS 路由，不可用时返回 `null` |
| 宿主 | `lib/cua-policy.js` | CUA 审批政策层（四级档位 + 让位）；判定抽成纯函数 `cuaGate` 便于单测 |
| 客户端 | `client.js` | `shell.overlay` 插槽里的桌宠，跑 WebGL 循环，收命令、发回执 |

路由用 `prefix` 而非 `exact`，因为形象包内部有相对路径导入（`whale/figure.js` → `../kit/rig.js`、
纹理 `tex/*.png`），只有路径形式的 URL 才能让浏览器按相对关系解析成功。

### 五个 HTTP 端点

| 端点 | 方向 | 用途 |
| --- | --- | --- |
| `/api/dsh-coopanion-pet/assets/*` | 宿主 → 浏览器 | 渲染内核、形象包、纹理 |
| `/api/dsh-coopanion-pet/events` | 宿主 → 浏览器（SSE） | 运行状态；Agent 下发的命令 |
| `/api/dsh-coopanion-pet/report` | 浏览器 → 宿主（POST） | 命令回执、用户回答、桌面侧状态 |
| `/api/dsh-coopanion-pet/speech` | 浏览器 → 宿主（POST） | 录音（base64 WAV）→ 识别文字；没装语音插件时回 501 |
| `/api/dsh-coopanion-pet/tts` | 浏览器 → 宿主（POST） | 文字 → 合成音频；没装 TTS 插件时回 501 |

不用 DSH 的 RPC 做上下行：本插件只需要「推一件事、回一件事」，自己的路由更直接，
也不依赖宿主内部接口的稳定性。

### 状态为什么要绕宿主一圈

探针实测（dsh 0.2.0-rc.2）显示，浏览器端的插件 `apply` 运行时**只有 `slots`、`connection`、
`loader`、`modules` 四个服务可用**，`sessions`、`conversation`、`theme`、`locale` 都取不到；
而 `shell.overlay` 是 root 作用域插槽，框架注入的标准 props（`GlobalStandardProps`）是空接口，
也没有会话信息。所以状态气泡不能由客户端自己取数。

宿主侧则拿得到：`agent/status` 事件（一轮对话的开始与结束）与 `tools/execute` 钩子（每次工具调用）。
因此状态由宿主采集、经 SSE 下发，客户端只负责显示。同一条通道也让 `pet_*` 工具能反向驱动页面。

### 工具定义为什么要自己转 schema

DSH 官方的工具都用 `defineTool()` 造，它把「属性上写 `required: true`」的写法提成对象级的
`required: [...]` 数组。直接调 `tools.register()` 绕过这一步，注册会报
`required is not supported on type "boolean"`。

`lib/define-tool.js` 做同一件事，但不依赖 `@deepseek-ai/dsh-tools`——那是宿主内部包，
版本一变就可能对不上。转换只有两条规则：标了 `required: true` 的属性名进 `required` 数组，
属性自己的那个标记去掉。

### 渲染内核为什么能直接搬

`kit/rig.js` 零 import，`kit/body.js` 只依赖 `rig.js`，形象包通过 `opts.kit` 注入渲染器。
这套内核不依赖 Coopanion 的 World 协议、socket 或 Electron，是干净的可移植单元。

## 已做的适配

移植时改动集中在这几处，其余照搬：

1. **指针改为坐标命中判定。** Coopanion 里桌宠跑在 Electron 透明窗口里，靠窗口级
   `setInteractive` 切换鼠标穿透。浏览器没有这个概念。本插件让覆盖层与其中所有元素始终
   `pointer-events:none`，把指针处理挂在 `window` 捕获阶段，用渲染内核每帧回报的命中圆
   按坐标判定：命中她本体、或命中她自己弹出的按钮条与气泡时才拦事件，否则原样放行。

   这样处理还避开了一个陷阱：`pointer-events` 从 `none` 切到 `auto` 时，浏览器不会把已在
   该位置的指针重定向过去，因此「悬停时才激活热区」的写法在真实点击下并不生效。

2. **不调用 `set({ theme })`。** 渲染内核的该方法会写 `document.documentElement.dataset.theme`，
   与 DSH 自己的主题机制（`body[data-ds-dark-theme]`）冲突。配色改由内核 CSS 的
   `prefers-color-scheme` 与气泡 CSS 的 DSH 令牌各自判断。

3. **帧循环加了 `dt` 上限。** 标签页切回或系统休眠后 `dt` 会非常大，不限制的话她会一帧冲过整个屏幕。

4. **音效去掉音频文件支路。** 上游会加载形象包自带的音频，本插件只用合成音，
   因此 `sfx.js` 去掉了 `usePack` 与解码逻辑，`play` 直接进合成器。

5. **气泡按需创建、随桌宠卸载。** 上游的气泡是页面固定元素，这里由插件创建并
   在卸载时移除，不留残余。

6. **状态来自宿主而非页面。** 见上文「状态为什么要绕宿主一圈」。

7. **装扮面板重写为插件内面板。** 上游是独立页面（`dress.html` + `dress.js`），
   本插件把它做成跟随桌宠的浮层，只保留配色与服装两条轴。

8. **状态上报不用 `keepalive`，且在途只留一条。** 她走动时位置每帧都在变，状态上报是高频的；
   浏览器在同一个 `keepalive` 请求还没落地时再次发起会把前一个取消掉（表现为 `ERR_ABORTED`），
   于是每次上报都变成「一次成功 + 一次被取消」。因此改为普通 fetch，并把位置量化到 10px 粒度，
   只有跨过一格或模式/装扮变了才发。用户的回答与命令回执走另一条必达路径（不受在途限制）。

**未验到的部分（如实说明）**：工具的端到端验证用的是「扮演页面的客户端」而非真实浏览器标签页——
因为探针在服务启动后几秒就开始轮询，而浏览器要十几秒才把桌宠加载完并连上 SSE，两者的时序在这个
验证环境里总是错开。因此「SSE 命令帧真的会让浏览器里的她说话/走路」这一段，是由以下两点合并支撑的：
（1）命令帧格式与 `runCommand` 的处理分支已逐条核对；（2）页面自身的执行能力（`api.say`、
装扮切换等）已在浏览器里单独验证通过。**真机上两者是同一个页面，链路是通的**，但没有一次
「真实浏览器 + 真实工具调用」的合并验证，建议首次使用时留意。

## 配置

偏好写在 `localStorage` 的 `dsh-coopanion-pet:prefs`（JSON）。右键菜单与装扮面板改的设置即时生效并落盘：

```json
{ "enabled": true, "sizeIndex": 1, "roamIndex": 0, "sound": true,
  "startShare": 0.78, "scheme": "deepseek-maid", "statusBubble": true, "lang": "auto" }
```

| 键 | 含义 |
| --- | --- |
| `enabled` | 是否显示桌宠（右键「隐藏桌宠」会置为 `false`，改回需手动编辑） |
| `sizeIndex` | 体型档位：`0` 小 / `1` 中 / `2` 大 |
| `roamIndex` | 漫游倾向：`0` 安静 / `1` 随意 / `2` 活跃 |
| `sound` | 音效开关 |
| `startShare` | 初始横向位置，占窗口宽度的比例 |
| `scheme` | 装扮，`配色-服装`，如 `claude-maid`、`deepseek-cape` |
| `statusBubble` | 是否显示状态气泡 |
| `lang` | 界面语言：`auto` 跟随浏览器，或 `zh` / `en` 显式指定 |
| `trail` | 是否显示走路足迹 |
| `fpsIndex` | 帧率档位：`0` 省电 / `1` 平衡 / `2` 流畅 |
| `cuaLevel` | 电脑操作审批档位：`ask-each-turn` / `ask-before-acting` / `ask-once` / `never-ask` |
| `dressPos` | 装扮面板的位置（拖动后记下） |

### 从页面里驱动她

客户端暴露了 `window.__dshCoopanionPet`，供验证脚本与将来的 Agent 接线使用：

```js
__dshCoopanionPet.say('【happy】你好呀。');   // 说话，可带标记
__dshCoopanionPet.ask('选一个？', ['甲', '乙', '丙']);  // 提问
__dshCoopanionPet.do('jump');                // 表情或动作
__dshCoopanionPet.walk(400, true);           // 走到横向 400px，true 为跑
__dshCoopanionPet.setScheme('claude-cape');  // 换装扮
__dshCoopanionPet.openDress(true);           // 开关装扮面板
__dshCoopanionPet.layout;                    // 当前布局快照
```
